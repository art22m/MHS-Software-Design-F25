### 1. [Диаграмма классов](class.md)

#### Описание Классов
Order - Хранит информацию о заказе на производство автомобиля (количество, комплектация, цвет), полученном от дилера.

ProductionPlan - Определяет запланированную последовательность сборки автомобилей на конвейере.

Car  - Основная сущность, идентифицирующая конкретный автомобиль (VIN, Модель) и его текущий Статус в процессе производства или ремонта.

AssemblySection  - Представляет физический участок конвейера, к которому привязаны определенные Ремонтные зоны.

RepairZone  - Физическая зона для устранения дефектов.

RepairPlace (РемонтноеМесто) - Единица, где может находиться один автомобиль для ремонта.

RepairTeam (РемонтнаяБригада) - Группа сотрудников, работающая посменно.

Employee (Работник) - Базовый класс для всех сотрудников, занятых в ремонте.

Repairer (Ремонтник) - Сотрудник, непосредственно выполняющий ремонт.

Foreman (Бригадир) - Руководитель РемонтнойБригады

Defect (Дефект) - Регистрирует факт обнаружения проблемы

Repair (Ремонт) - Фиксирует процесс устранения дефекта

### 2. [Диаграмма компонентов](component.md)


Данная диаграмма (C4 Level 3) отображает архитектуру системы.

Все логические компоненты инкапсулированы в едином бекенд-сервисе и используют единый API-интерфейс для взаимодействия с внешними клиентами (UI, СКК, Бухгалтерия). Предполагается также логически разделить код на несколько модулей, описанных ниже:


API Interface Единая точка приёма всех запросов.

Логика Управления Дефектами - Обрабатывает регистрацию и жизненный цикл дефектов и ремонтов.

Логика Управления Ресурсами - Управляет статусами ремонтных зон, мест, бригад и рабочих; отвечает за назначение заданий.

Логика Отчетности - Формирует все типы сводных отчетов по сменам и месяцам.

### 3. [Диаграмма развертывания](deployment.md)


Эта диаграмма (C4 Level 4) описывает развертывание системы. Предполагается что система развернута в k8s у облачного провайдера, либо в локальном цоде (если у предприятия есть свои сервера).

Основные компоненты развертывания:

Кластер Kubernetes (K8s) - Используется для оркестрации и масштабирования Deployment'а с Сервисом.

Монолитный Сервис Учета Дефектов - Является серверным приложением, обрабатывающим API-запросы и осуществляющим бизнес-логику

Nginx Ingress - Балансировщик входной нагрузки принимающий запросы и распределяющих их в контейнеры Deployment'а

База Данных PostgreSQL - Единое хранилище всех транзакционных и отчетных данных.

Клиентские Приложения - Веб-интерфейс и Мобильное Приложение взаимодействуют с системой через Nginx
