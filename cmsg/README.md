# cmsg. Система чата с поддержкой комнат

Система чата на C++ с клиент-серверной архитектурой, поддерживающая групповые комнаты для обмена сообщениями.

## Возможности

- **Многопоточный сервер** с использованием kqueue для асинхронной обработки соединений
- **Система комнат**: клиенты могут присоединяться к комнатам и обмениваться сообщениями внутри них
- **Бинарный протокол** с заголовками сообщений для надежной передачи данных
- **Масштабируемость**: сервер использует пул воркеров (количество равно количеству ядер CPU)

## Структура проекта

```
cmsg/
├── msglib/          # Библиотека с классами Socket и типами сообщений
├── server/          # Сервер приложения
├── client/          # Клиент приложения
└── CMakeLists.txt   # Корневой файл сборки
```

## Компоненты

### msglib

Библиотека, предоставляющая:
- **Socket**: RAII-обертка над POSIX сокетами с методами для работы с TCP соединениями
- **MsgType**: Перечисление типов сообщений (TEXT, CONNECT, DISCONNECT)
- **MsgHeader**: Структура заголовка сообщения (длина + тип)
- **kMaxPacketSize**: Максимальный размер пакета (4096 байт)

### server

Многопоточный сервер с архитектурой на основе воркеров:

- **RoomManager**: Управляет комнатами и клиентами
  - Добавление/удаление клиентов из комнат
  - Трансляция сообщений всем участникам комнаты (кроме отправителя)
  - Потокобезопасность через `std::shared_mutex`

- **Worker**: Воркер-поток для обработки клиентских соединений
  - Использует kqueue для мониторинга событий на файловых дескрипторах
  - Обрабатывает входящие сообщения и управляет отключениями
  - Каждый воркер обслуживает подмножество клиентов

- **Главный поток**: Принимает новые соединения и распределяет их между воркерами по round-robin

**Порт**: 8080

### client

Клиентское приложение для подключения к серверу:

- Подключение к указанной комнате при запуске
- Отправка текстовых сообщений в комнату
- Получение сообщений от других участников комнаты
- Команда `/exit` для корректного отключения

**Использование**: `./msgclient <RoomName>`

## Протокол

Сообщения передаются в бинарном формате:

```cpp
struct MsgHeader {
    uint32_t len;        // Длина payload в байтах
    MsgType msgType;     // Тип сообщения
};
```

Типы сообщений:
- **CONNECT**: Присоединение к комнате (payload = имя комнаты)
- **TEXT**: Текстовое сообщение (payload = текст сообщения)
- **DISCONNECT**: Отключение от сервера (payload пустой)

## Как собрать

```bash
mkdir build
cd build
cmake ..
make
```

После сборки будут созданы исполняемые файлы:
- `server/msgserver` - сервер
- `client/msgclient` - клиент

## Как запустить

### Запуск сервера

```bash
./server/msgserver
```

Сервер выведет количество запущенных воркер-потоков и начнет слушать на порту 8080.

### Запуск клиента

```bash
./client/msgclient <RoomName>
```

Например:
```bash
./client/msgclient general
./client/msgclient dev-team
```

Клиенты, подключенные к одной комнате, будут получать сообщения друг от друга.

### Пример использования

Терминал 1 (сервер):
```bash
./server/msgserver
# Server started with 8 worker threads.
```

Терминал 2 (клиент 1):
```bash
./client/msgclient general
# Connected to server. Joining room: general
# Type messages and press Enter. Type '/exit' to quit.
# You: Привет всем!
```

Терминал 3 (клиент 2):
```bash
./client/msgclient general
# Connected to server. Joining room: general
# [Room Message]: 3: Привет всем!
# You:
```

## Архитектура

### Поток данных

1. Клиент подключается к серверу
2. Главный поток сервера принимает соединение и распределяет его воркеру (round-robin)
3. Клиент отправляет сообщение типа CONNECT с именем комнаты
4. Воркер регистрирует клиента в RoomManager
5. Клиент отправляет текстовые сообщения типа TEXT
6. Воркер транслирует сообщение всем участникам комнаты через RoomManager
7. При отключении клиент отправляет DISCONNECT или сервер обнаруживает EOF

### Потокобезопасность

- **RoomManager**: Использует `std::shared_mutex` для чтения (broadcast) и записи (join/leave)
- **Worker**: Каждый воркер имеет свой `kqueue` и управляет своим набором клиентов
- **Socket**: Не копируется, перемещается через `Release()` для передачи между потоками

### Обработка ошибок

- Проверка размера пакета (максимум 4096 байт)
- Обработка разрывов соединения (EV_EOF в kqueue)
- Валидация типов сообщений
- Исключения при ошибках сетевых операций

## Технические детали

- **Стандарт C++**: C++23
- **Сборка**: CMake 3.8+
- **Платформа**: macOS/FreeBSD (использует kqueue)
- **Флаги компиляции**: `-Wall -Werror -Wextra-semi -O1 -g -fsanitize=address`
- **Максимальный размер пакета**: 4096 байт
- **Порт по умолчанию**: 8080

## Ограничения

- Сервер работает только на платформах с поддержкой kqueue (macOS, FreeBSD)
- Максимальный размер сообщения ограничен 4096 байтами
- Нет аутентификации и шифрования
- Нет персистентности (сообщения не сохраняются)
